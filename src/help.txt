The daemon keeps one external mapping alive on a ds-lite line by writing to it, learns the mapping's external address and port with STUN, and forwards inbound UDP and TCP to a target on the local network with the peer's source address preserved. It answers UPnP IGD, PCP and NAT-PMP on the LAN, and it can report on the carrier's filtering from outside the line.

Usage: ds-lite-punch --static-map R=ip:port [OPTIONS]
       ds-lite-punch --bind ip:port --target ip:port [OPTIONS]

Options:
      --static-map <R=IP:PORT>
          Hold the mapping for slot port R, forwarding inbound datagrams to ip:port on the local network. Repeatable, one entry per instance. Either this or the legacy --bind/--target pair is required.

      --bind <IP:PORT>
          Legacy single-map form: the relay socket on the CGNAT-facing address, which is the tuple the carrier maps. Requires --target.

      --target <IP:PORT>
          Legacy single-map form: the local endpoint inbound datagrams are forwarded to, with the peer's source address preserved. Requires --bind.

      --stun <HOST:PORT,...>
          STUN servers, comma-separated as host:port, tried in order and rotated when one falls silent. Default: stun.l.google.com:19302,stun.cloudflare.com:3478.

      --interval <SECS>
          Seconds between the STUN writes that keep the mapping alive. The writes are what the carrier sees, so this is the interval the mapping's lifetime depends on. Default 2, minimum 1.

      --gateway <IP>
          Next hop used to route STUN out the line the mapping is on. Without it the default route wins and STUN reports the wrong nat. Default 192.168.0.1.

      --state-dir <PATH>
          Directory for the published tuple, the facade's identity and the DeviceProtection store. The lease records and the epoch are kept at their own fixed path, /tmp/dslp. Both directories are on temporary filesystems, so neither survives a reboot. Default /run/ds-lite-punch.

      --slot-port-range <LO-HI>
          Port range the slot engine allocates from, written LO-HI. Ports in it must not overlap the relay socket. Default 30000-39999.

      --max-slots <N>
          Maximum concurrent slots. Default 32.

      --max-maps-per-client <N>
          Maximum mappings per client. Default 16.

      --gc-grace-factor <N>
          Grace multiple applied to a slot's lifetime before it is collected. Default 3.

      --max-refresh-attempts <N>
          The keepalive's budget. It bounds the refresh attempts for one flow whose conntrack entry has gone, and the number of flows kept alive at once. Default 8.

      --observation
          Report the named devices' live flows and touch nothing. This is the stage a new device is admitted from, before --keepalive arms the arm.

      --allowlist <PATH>
          File of IPv4 addresses, one per line, with # for comments. These are the devices the keepalive acts for. The list is a budget as well as an admission: a flow kept alive costs about half a packet a second at the default interval. The path is read at startup, so a typo fails the start.

      --keepalive
          Keep the named devices' mappings alive: the RFC conntrack lifetimes, plus the daemon's own writes on the device's behalf. Without this flag the allowlist is reported on and nothing is touched.

      --cdc <proc|nft|aya>
          How conntrack entries are removed: proc, nft, or aya. The nft backend is the default and the one this line is measured with.

      --pcp
          Answer PCP (RFC 6887) and NAT-PMP (RFC 6886) on UDP 5351, on the local network only, using the same slot engine as the UPnP facade. Off by default.

      --pcp-peer
          Answer the PCP PEER opcode with the mapping's own tuple. The datapath is endpoint-independent, so that opcode installs nothing and is otherwise refused.

      --upnp-port <N>
          Port the UPnP IGD facade serves on. Default 49152.

      --lan-ip <IP>
          Local address the facade binds its HTTP service to and joins the SSDP group on. Default 192.168.21.1.

      --upnp-name <NAME>
          Friendly name the facade reports in its device description. Default `ds-lite-punch IGD`.

      --no-upnp
          Turn the UPnP IGD facade off. Use it when another device on the local network already answers SSDP.

      --carrier-probe
          Count the cooperating helper's marked probe, and raise carrier-silent after the configured number of intervals with none. Arming this obliges the helper to run, because a helper that stopped and a carrier that stopped look the same to the counter.

      --carrier-probe-interval <SECS>
          Seconds expected between the helper's probes. Default 900.

      --carrier-probe-misses <N>
          Intervals of silence that raise carrier-silent. Default 3.

      --carrier-probe-poll <SECS>
          Seconds between readings of the counter's value. Default 5.

  -h, --help
          Print this text and exit.

  -V, --version
          Print version

EXIT STATUS
  0   the daemon ran, or --help or --version was printed
  2   the command line was rejected, and the message says why

ENVIRONMENT
  The procd service reads /etc/ds-lite-punch.env and turns its keys into the flags above. The key-by-key mapping is in the manual page's ENVIRONMENT section, which also names the three keys only the service reads.
